# DU Radar 작업 규칙

## 서비스 개요

- 서비스 이름은 `두레이더`입니다.
- 영어 표기는 `DU Radar`입니다.
- 대상 지역은 대구대학교 경산캠퍼스입니다.
- 학생과 교직원이 캠퍼스 지도에 핀을 찍어 학교 정보를 함께 모으는 커뮤니티 웹앱입니다.
- 사업단 프로그램, 사업단·행정실 위치, 분실물 안내, 건물별 라운지와 편의시설 정보를 하나의 지도에서 제공합니다.
- 흩어진 학교 정보를 사용자가 여러 사이트를 방문하지 않고 지도에서 확인하는 것이 핵심 목적입니다.

## 작업 원칙

- 화면의 시작점은 `public/index.html`입니다.
- 결과물은 브라우저에서 바로 실행되는 웹앱이어야 합니다.
- 휴대폰에서도 앱처럼 보이고 사용할 수 있도록 모바일 화면을 우선 확인합니다.
- 사용자가 요청하지 않은 기능은 추가하지 않습니다.
- 지도 중심의 단순한 흐름을 유지합니다.
- 작업이 끝나면 무엇을 바꿨는지와 어떻게 확인했는지를 짧게 안내합니다.

## 앱 파일 구조

- 앱 파일은 `server.js`, `public/`, `test/` 폴더를 기준으로 관리합니다.
- `public/`에는 브라우저에 공개할 화면·데이터·아이콘·로컬 라이브러리만 둡니다.
- `store/`에는 서버가 저장하는 JSON만 둡니다. 브라우저에서 직접 열리지 않아야 합니다.
- 캡처 파일과 미리보기 기록은 `old/` 폴더에 둡니다.

## 언어와 문구

- 화면 문구는 한국어와 영어를 모두 준비할 수 있도록 구조를 잡습니다.
- 기본 화면은 한국어입니다.
- 한국어 문장은 `~요` 말투로 씁니다.
- 한국어 화면에 `LIVE` 같은 영어 장식 딱지를 넣지 않습니다.
- 이모지는 사용하지 않습니다.
- 영어는 필요한 제품명, 버튼, 안내 문구에만 사용합니다.

## 사용자와 개인정보

- 로그인 기능은 만들지 않습니다.
- 학생과 교직원을 구분하지 않습니다.
- 이름, 학번, 전화번호 등 개인정보를 받지 않습니다.
- 행정실은 위치만 보여줍니다.
- 행정실 전화번호와 개인 연락처를 넣지 않습니다.
- 게시글이나 핀 등록에 개인정보 입력을 요구하지 않습니다.

## 지도와 외부 서비스

- 돈이 들거나 API 키가 필요한 지도·외부 서비스를 사용하지 않습니다.
- 필요한 지도 화면은 제공된 데이터와 로컬 파일로 구현합니다.
- 외부 API, 유료 지도 타일, 키가 필요한 SDK를 추가하지 않습니다.
- 패키지를 설치하지 않습니다.
- 필요한 라이브러리는 프로젝트 안에 파일로 보관하고 상대경로로 불러옵니다.

## 파일과 데이터

- 모든 경로는 상대경로를 사용합니다.
- `data` 파일은 프로젝트에서 직접 생성하며, 한 번 만든 뒤에는 사용자가 다시 만들라고 말할 때만 다시 생성합니다.
- 사용자가 제공한 원본 데이터 파일은 수정하거나 덮어쓰지 않습니다.
- 데이터 변경이 필요할 때는 기존 파일을 임의로 갱신하지 말고 먼저 요청을 확인합니다.
- `public/data/campus-map.json`과 `public/map-style.css`는 사용자가 제공한 원본 파일이므로 내용을 수정하거나 덮어쓰지 않습니다.

## 디자인

- 아이폰 앱처럼 깔끔하고 차분하게 만듭니다.
- 살짝 비치는 카드와 은은한 그림자를 사용합니다.
- 카드와 버튼 모서리는 둥글게 처리합니다.
- 정보가 주인공이 되도록 장식과 애니메이션을 과하게 넣지 않습니다.
- 지도, 핀, 검색, 필터, 상세 정보가 한눈에 이해되도록 구성합니다.
- 모바일에서 버튼과 탭이 잘리지 않도록 실제 화면 크기로 확인합니다.
